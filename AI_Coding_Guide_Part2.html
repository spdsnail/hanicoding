공통 지침·프로젝트 디자인·Git·긴 대화 관리까지 AI에게 맡기는 방법

01. 왜 공통 작업 규칙이 필요한가

프로그램을 여러 번 고치다 보면 “매번 같은 말을 반복하네”, “옛날 상태로 돌리고 싶다”, “대화가 너무 길어졌다”는 순간이 옵니다. 이 문제들을 AI에게 규칙을 한 번 알려 주는 것으로 해결합니다.

이 가이드에서 사용자가 관리할 지침 파일은 두 종류입니다. ① 모든 프로젝트에 적용할 공통 작업 규칙 ② 각 프로젝트의 디자인·요구사항 규칙입니다.

구분파일주요 역할
공통AGENTS.md (Codex) 또는 CLAUDE.md (Claude Code)쉬운 한국어, 작업·확인 절차, Git 관리
프로젝트별프로젝트명_DESIGN.md색상, 화면 구성, 디자인, 개별 요구사항
공통 규칙 파일은 각 도구가 정해진 위치에서 읽지만, 프로젝트명_DESIGN.md는 특별한 자동 인식 파일명이 아닙니다. 공통 규칙에서 읽도록 명시해야 합니다.

02. 공통 지침 파일 만들기

처음에는 현재 프로젝트 폴더에 공통 규칙을 만들어 시험할 수 있습니다. 여러 프로젝트에 동일한 규칙을 적용하려면 각 도구가 지원하는 사용자 전역 지침 위치에 배치해야 합니다. 프로젝트 안의 파일 하나가 모든 다른 프로젝트에 자동 적용되는 것은 아닙니다.

AI에게 이렇게 말하세요
이 프로젝트 폴더에 공통 작업 규칙 파일을 만들어줘. 내가 쓰는 도구에 맞는 이름으로 만들어줘 (Codex는 AGENTS.md, Claude Code는 CLAUDE.md). 내용은 아래 그대로 넣고, 만든 뒤에 파일 위치를 알려줘.

[아래 ‘공통 작업 규칙 템플릿’을 여기에 붙여넣기]
복사용 공통 지침 예시
# 공통 작업 규칙

## 사용자와 대화
- 사용자는 코딩 초보자다. 쉬운 한국어로 설명한다.
- 코드 전체를 답변에 붙여넣기보다 파일을 직접 수정한다.
- 작업 후 변경 내용과 확인 방법을 짧게 알려 준다.

## 작업 방식
- 작업 시작 전 현재 프로젝트와 변경 사항을 확인한다.
- 기존 기능을 보존하면서 요청한 범위만 수정한다.
- 가능한 테스트를 실행하고 결과를 사실대로 보고한다.
- 중요한 삭제·폴더 밖 접근·외부 업로드는 먼저 확인받는다.

## 프로젝트별 디자인·진행 기록
- 현재 프로젝트 폴더 이름과 일치하는 프로젝트명_DESIGN.md 파일을 찾는다.
- 프로젝트 작업을 시작할 때 해당 파일의 디자인·진행 기록을 읽는다.
- 파일이 없거나 후보가 여러 개이면 임의로 선택하지 말고 질문한다.
- 다른 프로젝트의 디자인 파일을 적용하지 않는다.
- 사용자가 디자인·진행 내용 변경을 요청하면 해당 파일도 함께 갱신한다.
- 작업을 마무리하거나 대화를 옮기기 전 이 파일에 현재 상태와 다음 작업을 갱신한다.

## Git
- 정상 작동이 확인되면 변경 사항을 Git에 자동 저장한다.
- Git이 없다면 먼저 설정을 제안하고 승인 후 초기화한다.
- 비밀번호·API 키·개인정보 파일은 Git 저장 대상에서 제외하고 외부 공유·배포에도 포함하지 않는다.
- GitHub 등 원격 업로드는 사전 승인받는다.
- 강제 되돌리기나 기록 삭제는 사용자에게 먼저 확인한다.
지침은 행동을 유도하지만 모든 실행을 보장하지 않습니다. 특히 Git 커밋, 파일 삭제, 외부 업로드는 실제 실행 결과를 확인해야 합니다.

Codex 공식 자료: AGENTS.md 안내 · Claude 공식 자료: CLAUDE.md 안내

문제가 생기면 규칙을 무시하는 것 같을 때 “공통 작업 규칙 파일을 다시 읽고 지금 작업에 적용해줘”라고 말하세요. 중요한 규칙이 묻히지 않도록 파일은 짧고 명확하게 유지합니다.

작업 중 추가하거나 바꾸고 싶은 내용이 생기면 AI에게 공통 작업 규칙이나 프로젝트별 디자인·진행 기록을 수정해 달라고 하세요. 자주 쓰는 지시 패턴은 메모해 두거나 공통 규칙에 추가하면 반복 설명을 줄일 수 있습니다.

03. 프로젝트명_DESIGN.md 만들기

각 프로젝트 폴더에 폴더이름_DESIGN.md 파일을 하나 둡니다. 이 파일은 디자인 지침과 작업 진행 기록을 함께 관리합니다. 화면의 색상·배치뿐 아니라 구현된 기능, 결정한 사항, 남은 작업, 알려진 문제도 기록합니다.

이미 마음에 드는 화면이 있을 때 — AI에게 이렇게 말하세요
지금 이 프로그램의 디자인을 분석해서 ‘폴더이름_DESIGN.md’ 파일로 정리해줘 (폴더 이름과 똑같이 시작하는 이름으로). 현재 구현된 기능과 주요 결정 사항, 남은 작업도 함께 기록해줘. 이 파일은 현재 프로젝트 전용으로 사용하고 작업하면서 계속 갱신해줘.
복사용 프로젝트별 파일 예시
# 메모장 디자인 및 작업 기록

적용 대상: 메모장 프로젝트만

## 디자인
- 화면: 단정하고 읽기 쉬운 메모장
- 버튼: 둥글고 클릭하기 편하게
- PC와 모바일에서 모두 사용 가능

## 구현된 기능
- 메모 추가·수정·삭제
- 브라우저에 메모 저장

## 현재 상태와 결정 사항
- 기존 기능을 유지하며 수정
- 마지막으로 정상 확인한 기능을 기록

## 알려진 문제·다음 작업
- 알려진 문제: 없음(발견되면 기록)
- 다음 작업: 메모 검색 기능 추가

이 파일명은 자동 인식되는 표준 지침 이름이 아닙니다. 공통 작업 규칙에서 현재 프로젝트 폴더 이름과 일치하는 파일을 읽도록 지정해야 합니다. 다른 프로젝트의 파일은 사용하지 않습니다.

04. Git 자동 버전 관리

Git 명령어는 배우지 않습니다. 규칙을 공통 작업 규칙에 적어 두면 AI가 정상 작동이 확인된 변경 사항을 저장하도록 맡길 수 있습니다.

Git이 해 주는 일

Git은 ‘프로그램의 타임머신’입니다. 기능이 하나 완성될 때마다 그 시점의 파일 상태를 기록합니다. 저장된 한 칸을 커밋(commit)이라고 부릅니다. 아래처럼 기록이 쌓입니다.

저장 기록 예시 · 위가 최신
a1b2c3d  메모 검색 기능 추가
d4e5f6a  삭제 버튼 추가
9f8e7d6  전체 배경색을 베이지로 변경
3c4b5a6  메모장 기본 기능 처음 만듦

Git이 설치되어 있지 않다는 안내가 나오면 AI에게 “내 운영체제에서 Git을 설치하는 방법을 단계별로 알려줘”라고 하세요. 설치 파일은 Git 공식 다운로드에서 받을 수 있습니다. 이름과 이메일 설정을 물으면 AI의 안내를 따라 설정하세요.

Git과 GitHub는 다릅니다

Git은 내 컴퓨터에서 변경 이력을 관리하는 도구입니다. GitHub는 Git 프로젝트를 인터넷에 보관하고 공유할 수 있는 서비스입니다. Git에 저장했다고 자동으로 GitHub에 업로드되지는 않습니다. Git 기록만으로는 컴퓨터 고장에 대비한 외부 백업이 되지 않습니다.

저장 상태를 확인하고 싶을 때
현재 프로젝트의 Git 저장 기록을 최신순으로 보여줘. 마지막으로 정상 작동을 확인하고 저장한 버전을 알려줘.

실제 자동 저장 여부는 도구 권한과 설정에 따라 달라질 수 있으니, 중요한 작업 후에는 AI에게 최근 커밋이 만들어졌는지 확인해 달라고 하세요.

05. 이전 버전으로 안전하게 되돌리기

프로그램이 잘못 수정되었다면 저장 기록을 확인하고 원하는 상태를 선택합니다. 무조건 “마지막 버전으로 돌려 줘”라고만 하면 최근에 저장하지 않은 작업이 사라질 수 있습니다.

AI에게 이렇게 말하세요
최근 변경으로 문제가 생겼습니다. 현재 저장되지 않은 변경 사항을 먼저 확인하고, 정상 작동하던 Git 커밋 후보를 보여 주세요. 어떤 파일과 내용이 바뀌는지 설명한 뒤 제 승인을 받아 안전한 방법으로 복원해 주세요. 현재 작업 내용은 임의로 삭제하지 마세요.
Git의 강제 초기화·기록 삭제는 복구하기 어려울 수 있습니다. 사용자의 승인 없이 실행하지 않도록 공통 규칙에 포함하세요.

06. 대화가 길어졌을 때 이어서 작업하기

새 대화를 열어야 할 때는 응답이 눈에 띄게 느려지거나, 앞에서 정한 디자인·말투를 잊거나, 이미 해결한 문제를 반복할 때입니다. 중요한 상태를 채팅에만 남기지 않고 현재 프로젝트의 폴더이름_DESIGN.md에 함께 기록합니다. 별도의 PROJECT_STATUS.md 파일은 만들지 않습니다.

기존 대화 마무리 — AI에게 이렇게 말하세요
새 대화에서 작업을 이어갈 수 있도록 현재 프로젝트의 폴더이름_DESIGN.md를 갱신해줘. 기존 디자인 규칙은 유지하면서 프로젝트 목적, 구현된 기능, 주요 파일, 결정한 규칙, 해결되지 않은 문제, 다음 작업을 간단히 정리해줘.
새 대화 시작 — AI에게 이렇게 말하세요
현재 프로젝트의 공통 작업 규칙 파일과 폴더이름_DESIGN.md를 읽어줘. 구현된 기능과 남은 작업을 간단히 요약하고, 기존 기능을 유지하면서 다음 작업을 이어갈 준비를 해줘.

새 대화에서도 같은 프로젝트 폴더를 열어야 합니다. 도구 자체의 대화 재개 기능이 있다면 함께 사용할 수 있습니다.

07. 큰 프로그램을 단계별로 만들기

기능이 많아질수록 한 번에 전부 만들기보다 작은 작업으로 나누어 진행합니다.

AI에게 이렇게 말하세요
이 프로젝트에 기능을 추가하려고 합니다. 먼저 현재 구조를 확인하고, 기존 기능을 망가뜨리지 않도록 작업을 작은 단계로 나누어 계획해 주세요. 각 단계의 완료 기준과 확인 방법을 제시하고, 제 확인 후 첫 단계부터 진행해 주세요.

권장 반복 흐름

요청 → AI 수정 → 테스트 → 사용자 확인 → Git 저장 → 다음 기능

설명은 짧게 받되, 무엇을 변경했는지와 어떻게 확인했는지는 빠뜨리지 않도록 합니다.

08. 기존 기능을 유지하며 수정하기

새 기능을 넣은 뒤 이전 기능이 망가지는 일을 회귀 오류라고 합니다. AI에게 새 기능뿐 아니라 기존 기능도 함께 확인하도록 요청합니다.

사용자 확인표

AI가 테스트 코드를 실행하는 것과 사용자가 화면을 확인하는 것은 서로 보완적인 절차입니다.
문제가 생기면

기능 하나가 계속 망가진다면 “그 기능이 망가지지 않도록 자동 점검(테스트)을 만들고, 앞으로 수정할 때마다 실행해줘”라고 요청하세요. 코드를 이해할 필요 없이 AI가 점검기를 만들어 줍니다. 다만 실제 화면 동작은 직접 확인해야 할 수도 있습니다.

09. 여러 프로젝트 관리하기

프로젝트가 늘어나도 폴더와 파일 이름 규칙만 지키면 섞이지 않습니다.

폴더 구조 예시
AI프로젝트/
├─ 메모장/
│  ├─ index.html, style.css, app.js
│  └─ 메모장_DESIGN.md       ← 이 프로젝트 전용 디자인 & 작업기록
├─ 가계부/
│  ├─ ...
│  └─ 가계부_DESIGN.md

(공통 작업 규칙은 한 곳: 사용자 전체용 위치 또는 각 폴더의 AGENTS.md / CLAUDE.md)
파일프로젝트마다 따로?누가 관리?
공통 작업 규칙 (AGENTS.md / CLAUDE.md)아니오, 전체 공통내가 (AI에게 말로 고치게 함)
프로젝트명_DESIGN.md예내가 (AI에게 말로 고치게 함)

한 번에 폴더 하나만 열기. 여러 프로젝트가 한 대화에 섞이면 AI가 파일을 헷갈릴 수 있습니다. 공통 규칙은 도구가 지원하는 사용자 전체용 위치에 두거나, 프로젝트마다 같은 내용으로 적용할 수 있습니다.

10. 프로그램 배포하고 공유하기
